# AuthForge
認証技術を学ぶためのハンズオン開発プロジェクト

シリーズ全体の解説は、Zennの記事 [AuthForge シリーズ全体像](https://zenn.dev/shogo00713/articles/authseries-overview) にまとめています。
このシリーズを書いたきっかけや、記事のおすすめの読み方もそちらに書いているので、まずは先にご覧ください。

## 名前の由来

AuthForgeは、**Auth**（認証・認可）と**Forge**（鍛造する・鍛える、築き上げる）を組み合わせた名前です。
努力して一つずつ積み上げながら、認証を理解していくプロジェクトとして名付けました。

## このリポジトリについて

認証技術について自分で学んだことを、他の人にもわかりやすく追えるように記事としてまとめました（**理論編**）。
このリポジトリは、その内容を実際に自分の手で実装してみたもので、各ディレクトリがその実装にあたります。
さらに、実装に取り組んだ過程も記事にまとめています（**実践編**）。

各シリーズの理論編・実践編の記事へのリンクは、それぞれのディレクトリのREADMEに載せています。
また、各技術を横に並べて整理した基礎編 [認証と認可の違いとは？ホテルの例でわかる各技術の役割](https://zenn.dev/shogo00713/articles/authnandauthz-theory) もあります。

### 進め方

実装は、基本的に次のようなステップを踏んで進めています。

1. **実装**: 対象の仕組みを作る（構成する）
2. **観察**: DevToolsやWiresharkなどで、実際にやり取りされる値を観察する
3. **攻撃**: それに対して攻撃を行い、攻撃が通ることを確認する
4. **対策**: 対策を入れて、攻撃が通らなくなることを確認する

各ディレクトリのREADMEの「ハンズオンの流れ」に、実際に進めたステップを載せています。

## 補足

このリポジトリは学習用のコードです。現時点では、クローンしてすぐに動かせるような状態にはなっていません。実践編の記事と照らし合わせながら、参考程度に読み物として見てください。

* パスワードファイル（`.htpasswd`・`.htdigest`）、証明書、署名用の鍵、`.env`などはリポジトリに含めていません（`.gitignore`で除外しています）。動かすには、自分で用意する必要があります
* 攻撃を再現するため、意図的に脆弱な実装や、検証を外す危険なスイッチ（第4弾の脆弱な検証エンドポイント`/me-vulnerable`・`/me-rs256-vulnerable`、第6弾の`INSECURE_SKIP_NONCE_CHECK`・`INSECURE_SKIP_AUD_CHECK`など）を含んでいます。本番環境や実際のサービスでは使わないでください

> **注意:** 攻撃の再現は、すべて自分で構築したローカル環境・テストアカウントのみを対象としています。他人のサービスやシステムに対して試さないでください。
